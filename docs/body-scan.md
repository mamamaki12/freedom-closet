# 体の写真から3Dモデルを作る

## しくみ
- 設定 →「体の3Dモデル」→「体の写真で作る」。正面と横向きの2枚（横はとばせる）
- 写真は端末の中で MediaPipe Pose（`@mediapipe/tasks-vision`）に読ませ、骨格の点と人の形の切り抜き（マスク）を得る（`src/body/scan.ts`）
  - 読み取りのモデル（pose_landmarker_full、約9MB）は初回だけ Google のサーバーからダウンロードする。写真は送らない
  - 別の場所に置くときは `VITE_POSE_MODEL` にURLを入れる
- 切り抜きを高さごとに輪切りにして、胴・脚・腕の幅を測る。横向きの写真から厚みを測る（`src/body/measure.ts`）
  - すべて身長を1とした割合。ありえない値は `sane()` で人の体の範囲に収める
  - 腕が胴についていると胴の幅に腕が混ざるので、腕の分を引いて「少し不正確かも」と出す
  - まっすぐ立って腕を下ろした写真でなければ（ジャンプ・大きなポーズ・座っている）、撮り直しをお願いする
  - 測る高さは骨格の点で決める（`marks`）：胸はわきの下（胴と腕のあいだにすき間が出る高さ）の左右の胴の端どうし、ウエストは肩の点と腰の点のあいだの65%、ヒップは95%、太ももは腰とひざの中間、ふくらはぎはひざから足首の35%。幅は1行でなく上下の帯（身長の約0.4%）の中央値
  - 横向きの写真の高さは、頭から足までの割合でなく、横向きの写真の肩・腰・ひざ・足首の点に合わせて移す（髪の盛り上がりや足の写り方で数%ずれるため）
  - 肩幅は、肩の点の高さでの切り抜きの幅（骨格の点の間隔より、実測とよく合った）
  - 人とみなす境目は0.6（背景のある実写真では、0.5だと切り抜きが背景側に約1%はみ出した）
- 写真で測った値と身長・体重から、胸囲・ウエスト・ヒップ・太ももの目安（cm）を出す（`src/body/sizes.ts`。画面は `BodySizes`）。写真だけ・身長体重だけよりも、組み合わせたほうがよく当たる。式は下の「採寸の精度」
  - 3Dの体型も、この目安に向けて胸・ウエスト・ヒップ・太もも・ふくらはぎ・肩の太さを少し直す（`calibrateScan`、最大±15%）
  - 腕の太さは、上腕は肩からひじの7割、手首はひじから手首の85%の位置で写真から測り（`marks.upperArm`・`marks.wrist`）、身長（と体重）と組み合わせた式で出す。写真の値をそのまま使うと細めにずれる。腕が胴とつながって測れなかったときは身長・体重だけの式
  - 体重が未登録なら写真と身長だけの式（ずれは大きめ）、身長が未登録なら cm の目安は出さない。体重が未登録でも、3Dの腕の太さだけは写真と身長の式で直す
- 横の写真がないときの胴の厚みは、幅 × 段ごとの比（`TORSO_DEPTH_RATIO`：胸のあたり 0.80 前後、股の近く 0.69。BodyM で横の写真から測った比の中央値）。写真がないときの標準体型も同じ比
- 股の高さ（股下）は、写真で測った値を平均（身長の約45.7%）に強く寄せる（`inseamRatio`）。胴の段と目安の高さは、肩から股までをその分だけ伸び縮みさせる
- MediaPipe は GPU（WebGL）で動かす。CPU だと、写真によっては人の切り抜きで内部エラー（`Check failed: 1 == ChannelSize()`）になって落ちるため（実在の写真34枚中19枚で起きた）。WebGL が使えない端末では CPU にし、落ちたら部品を作り直して余白を増やし、もう一度だけ試す
- 服を着て撮った分をさし引く（`fitClothes`）：肩・腰・ひざなどの骨格の点は服に影響されにくいので長さはそのまま使い、胴と脚の太さは身長・体重から想定される太さ（標準体型）の1.2倍までに抑える。半分以上の段が想定よりずっと太ければ「ゆったりした服」と知らせる。身長か体重が未登録なら何もしない
  - 「ゆったりした服」のときは、胸囲などの cm の目安も服の分だけ大きく出るので、目安は出さずに撮り直しを案内する（BodyM の下着のシルエットで「ゆったり」になったのは2,495人中3人）
  - 下着のシルエット（BodyM 24人）では誰も「ゆったり」にならず、432段のうち4段しか変わらなかった。服を着たファッション写真12枚では、コートやロングコートの5枚が「ゆったり」になり、見た目が標準に近い体になった
- 標準体型（写真がないとき、`defaultScan`）の太さの係数は BodyM の24人に合わせた：体格指数が1増えるごとに、正面の幅は約1.6%、おなかは約2.6%、厚みは約3%。合わせる前は体重の効き方が2〜3倍強く、ウエストで14%・ヒップで17%ずれていたのが、3.5%・9%になった
- 保存するのは数字だけ（`localStorage` の `freedom-closet:body-scan`）。写真は保存しない
  - コーデ提案でClaudeに送る `Profile` とは分けてあり、外に送らない
- 3Dモデルは、測った輪切りの楕円を積み重ねて作る（three.js、`src/body/model3d.ts`）。服も同じ形を少しふくらませて作り、服の写真を模様として貼る
- コーデの一覧では画像にして表示し、タップで指で回して見られる（`src/body/Figure3D.tsx`）。WebGL が使えない端末では平面のイラスト（`OutfitFigure`）

## 実在の人の写真で試した結果（2026-10-30）
- Amazon が公開している体型データ BodyM（実在の人の正面・横のシルエットと、巻き尺での実測値。testA の24人）で、読み取った体型と実測値を比べた
  - 胸まわり ±5%、ウエスト ±3%、ヒップ ±3%、脚の長さ ±3%、腕の長さ ±6%、太ももまわり +13%（太め）、肩幅 +22%（データの「肩幅」は骨の幅で、こちらは体の外側の幅なので定義が違う）
  - ※ 2026-11-04 に人数を増やして測り直したところ、写真の数字は身長・体重だけの見積もりより当たりが悪かった（下の「採寸の精度」）。上の数字は24人の平均のかたよりで、1人ずつのずれは見ていなかった
  - 試して直したこと：腕が肩のすぐ下で胴と重なるのを「腕がついている」と誤判定していた（24人全員）→ わきの下より上は数えない。太ももがくっついていると股を低く測っていた（脚が1割短くなる）→ 腰とひざの点からの見積もりより下にしない。横向きで左右の脚がずれていると厚く出る → 幅の1.15倍まで
- 服を着たファッション写真34枚（ECON のサンプル）：19枚はジャンプや大きなポーズなので撮り直しのお願いに、3枚は体の一部が写っていない、12枚を読み取れた。コートやスカートの写真は服の形が体型になる（コートで胴が太くなる）ので、下着か体にぴったりした服で撮る案内は必須

## 採寸の精度（2026-11-04）
BodyM（Amazon、実在の人のシルエットと身長・体重、3Dスキャンで測った14か所の実測値）を人数を増やして使い、式を合わせる人（train 2018人）と確かめる人（testA 87人・testB 400人）を分けた。testB は撮る場所・カメラの向き・明るさをばらばらにした写真から作ったシルエットで、アプリの使い方に近い。数字は実測値との平均のずれ（testB）。

| | 胸囲 | ウエスト | ヒップ | 太もも | ふくらはぎ |
|---|---|---|---|---|---|
| 前のやり方（写真の輪切りのだ円の周） | 14.9cm（-15%） | 8.8cm | 5.3cm | 2.8cm | 3.0cm |
| 身長・体重だけ（前の標準体型の周） | 6.7cm | 5.2cm | 7.6cm | 3.8cm | 3.1cm |
| 今回：写真＋身長・体重の目安 | **2.9cm** | **3.1cm** | **2.2cm** | **1.8cm** | **1.3cm** |
| 今回：写真＋身長（体重なし） | 5.2cm | 3.8cm | 3.8cm | 3.1cm | 1.7cm |

- 分かったこと：前のやり方の写真の数字は、身長・体重だけの見積もりより実測との相関が低かった（testB でウエスト 0.90 対 0.94、ヒップ 0.85 対 0.92、腕の太さ 0.28 対 0.90）。切り抜き自体のずれは小さく（シルエットとの幅のずれは中央値0.6%）、原因は測る高さ（胸の段が腕の重なりでわきの下より下になる）、横向き写真の高さの合わせ方、輪切りのだ円と実際の周の違いだった
- 3Dの体型の太さも、実測との相関が上がった（testB、`calibrateScan` の後）：胸 0.91→0.94、ウエスト 0.91→0.94、ヒップ 0.85→0.89、太もも 0.83→0.93
- 胸囲・ヒップ・太ももは男女で形が違うので、式に「メンズ／レディース」の設定を入れている（未設定なら真ん中）
- あとから直したこと（testB の数字）
  - 横の写真がないときの胴の厚み：厚み÷幅を胸 0.68 → 股の近く 0.80 と、下ほど厚く見積もっていた（実際は逆で、胸のあたりがいちばん厚い）。横の写真で測った厚みとの比が、0.84〜1.06（胸が薄く、下腹が厚い）から 0.92〜0.99 になった。写真がないときの標準体型も同じ比にしたら、標準体型の周のずれも 胸 6.7→4.4cm、ウエスト 5.2→4.2cm、ヒップ 7.6→5.7cm に減った
  - 股下：写真の股の高さは撮り方で平均 -2.0cm（testA）〜 +3.8cm（testB）ずれ、身長の45.7%と決めたほうが当たった（写真の値の効き目は1割弱）。股下のずれ 4.2→1.7cm（testA は 2.5→1.8cm）
  - 腕の太さ：上腕を肩からひじの4割で測っていたので、腕を下ろした人の8割以上で胴まで測ってしまい、全員同じ値（身長の5%）になっていた。7割の位置にしたら測れる人が 16%→92%。3Dの上腕の周のずれは、体重なしで 4.1→2.2cm（相関 0.28→0.76）、体重ありで 1.25→1.15cm
- 背景のある実写真：正解の切り抜きつきの街のファッション写真（Clothing Co-Parsing、Apache-2.0、全身が写った927枚）で、MediaPipe の切り抜きの幅のずれは中央値で胸1%・ウエスト1.4%・ヒップ1.5%・太もも1.5%。ただしウエスト・ヒップ・太ももでは10枚に1枚が20%以上ずれる（腕・かばん・手が胴や脚とくっついて写る）ので、撮り方の案内（腕を体から離す）が大事。重いモデル（pose_landmarker_heavy、約30MB）でもほとんど変わらなかったので、今のモデル（約9MB）のまま
- BodyM のデータは CC BY-NC 4.0（非商用）。式の係数はそこから合わせているので、有料で配るときは確認が必要

### 採点のしかた（`tools/body-eval/`）
1. `python3 tools/body-eval/fetch_bodym.py <dir> train`（testA・testB も）で BodyM を取ってくる（リポジトリには入れない）
2. `python3 tools/body-eval/mediapipe_cache.py <dir> <split> pose_landmarker_full.task <cache>`：シルエットを写真にして MediaPipe（Python 版、`pip install mediapipe`）に読ませ、骨格の点と切り抜きを保存する。1枚0.1秒ほど
3. `npx tsx tools/body-eval/run.ts <dir> <cache> <split> > out.jsonl`：アプリの採寸コード（`measure.ts`）をそのまま当てる
4. `python3 tools/body-eval/fit.py train.jsonl testB.jsonl > src/body/sizeModel.json`：目安の式を train で合わせる（testB は画面の「±」に使う平均のずれを測るだけ）
5. `npx tsx tools/body-eval/score.ts testB.jsonl`：目安と3Dの体型のずれを表にする
