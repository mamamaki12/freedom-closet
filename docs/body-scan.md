# 体の写真から3Dモデルを作る

## しくみ
- 設定 →「体の3Dモデル」→「体の写真で作る」。正面と横向きの2枚（横はとばせる）
- 写真は端末の中で MediaPipe Pose（`@mediapipe/tasks-vision`）に読ませ、骨格の点と人の形の切り抜き（マスク）を得る（`src/body/scan.ts`）
  - 読み取りのモデル（pose_landmarker_full、約9MB）は初回だけ Google のサーバーからダウンロードする。写真は送らない
  - 別の場所に置くときは `VITE_POSE_MODEL` にURLを入れる
- 切り抜きを高さごとに輪切りにして、胴・脚・腕の幅を測る。横向きの写真から厚みを測る（`src/body/measure.ts`）
  - すべて身長を1とした割合。ありえない値は `sane()` で人の体の範囲に収める
  - 腕が胴についていると胴の幅に腕が混ざるので、腕の分を引いて「少し不正確かも」と出す
  - まっすぐ立って腕を下ろした写真でなければ（ジャンプ・大きなポーズ・座っている）、撮り直しをお願いする
- MediaPipe は GPU（WebGL）で動かす。CPU だと、写真によっては人の切り抜きで内部エラー（`Check failed: 1 == ChannelSize()`）になって落ちるため（実在の写真34枚中19枚で起きた）。WebGL が使えない端末では CPU にし、落ちたら部品を作り直して余白を増やし、もう一度だけ試す
- 服を着て撮った分をさし引く（`fitClothes`）：肩・腰・ひざなどの骨格の点は服に影響されにくいので長さはそのまま使い、胴と脚の太さは身長・体重から想定される太さ（標準体型）の1.2倍までに抑える。半分以上の段が想定よりずっと太ければ「ゆったりした服」と知らせる。身長か体重が未登録なら何もしない
  - 下着のシルエット（BodyM 24人）では誰も「ゆったり」にならず、432段のうち4段しか変わらなかった。服を着たファッション写真12枚では、コートやロングコートの5枚が「ゆったり」になり、見た目が標準に近い体になった
- 標準体型（写真がないとき、`defaultScan`）の太さの係数は BodyM の24人に合わせた：体格指数が1増えるごとに、正面の幅は約1.6%、おなかは約2.6%、厚みは約3%。合わせる前は体重の効き方が2〜3倍強く、ウエストで14%・ヒップで17%ずれていたのが、3.5%・9%になった
- 保存するのは数字だけ（`localStorage` の `freedom-closet:body-scan`）。写真は保存しない
  - コーデ提案でClaudeに送る `Profile` とは分けてあり、外に送らない
- 3Dモデルは、MakeHuman（CC0 の人体データ）の素体を元にする（下の「3Dの人体モデル」）。写真で測った数字に合わせて素体を変形し、服は素体にぴったりのメッシュから切り出して、服の写真を貼る
- コーデの一覧では画像にして表示し、タップで指で回して見られる（`src/body/Figure3D.tsx`）。WebGL が使えない端末では平面のイラスト（`OutfitFigure`）

## 3Dの人体モデル（2026-11-02）
以前は輪切りの楕円を積み重ねたマネキン（角張った肩、顔なし）だった。外部の素材・ツールを調べて、MakeHuman の人体データを使う形に置き換えた。

### 調べて見送ったもの
- Ready Player Me などのアバター作成サービス：体型が数種類のプリセットだけで、測った数字に合わせられない
- 仮想試着のAPI（FASHN、Kolors など）：本人の写真をクラウドに送る必要があり、「体の写真は端末の外に出さない」方針に合わない。有料
- SMPL 系の人体モデル：商用利用にライセンスが必要
- mannequin.js：軽いが見た目が人形で、質の改善にならない

### 使ったもの
- MakeHuman の素体メッシュ・体型ターゲット・骨格（makehumancommunity/makehuman、データは CC0）
  - `sh tools/body/fetch-makehuman.sh` で必要なファイルだけ取ってきて、`node tools/body/build.mjs` で `src/body/assets/human.glb`（約380KB）を作る。できた glb はリポジトリに入れてあるので、ふだんは作り直さなくてよい
  - 作るときに、腕を体の横に下ろしたポーズにし、男女・体重の差を6つの「モーフ」（頂点の差分）にまとめる。胴・腕・脚・頭のどれに属するかの重みと、肩・ひじ・手首・足などの目印の位置も一緒に入れる
  - 圧縮は gltfpack（meshopt）。三角形は約3万で、スマホでも軽い
- 体型への当てはめ（`src/body/human.ts`）
  - 身長・体重だけのときは、モーフを混ぜるだけ（体格指数で太さ、メンズ／レディースで形）
  - 写真で測ったときは、測った高さ（あご・肩・股・足首）に合わせて縦を伸び縮みさせ、胴（5段）と脚（4段）の幅・厚みをなめらかな曲線で合わせる。段ごとに別々の倍率を掛けるとでこぼこになるので、少ない点を通る曲線にしてある
- 服（`src/body/garments.ts`）
  - 素体にぴったりの「タイツ」と「スカート」のメッシュから、えり・すそ・袖の位置で切り出す。胸の下は体のくぼみに沿わせず、まっすぐ垂らす
  - 背中は、高さごとの断面を外側から包む形（凸包）に広げ、まわりとならす。背骨やおしりの谷に布が食い込んで折れ目ができない
  - すその切り口は、残す頂点と切る頂点の間の辺の上に置く（切り口が内側へ折れ込まない）
  - 重ね着（`Layers`）：着た服のいちばん外側を、胴の軸のまわりの角度と高さの区画ごとに覚え、上に着る服をそれより外へ出す（ニットのすそからスカートが突き抜けない）
  - 胴の前には服の写真を1枚貼り、背中・袖・パンツには写真の一部を生地の見本として敷き詰める。材質は「前・背中など・袖」の3つに分ける
  - 前の写真は、脇（胴の軸のまわりの向きで、前のまん中から60〜70°あたり）から真横の少し手前にかけて少しずつ生地の見本に切り替え、前と背中の境目では見本だけにする。写真の服は体より細く写ることが多いが、脇に継ぎ目が出ない。ハンガーに掛けた長袖の写真で、胴の脇に垂れて写った袖や影も見えなくなる
  - 背中の見本は、写真の柄に重なる位置から、まっすぐ前から当てる。コート・ワンピースのように上下2枚に分かれる服も、上と同じ当て方にして背中の模様をつなげる
  - 切り替えるところで写真の柄と見本の柄がずれて二重に見えないように、脇の近くで、見本を縦・横にどれだけずらすと写真の柄にいちばん重なるかを高さごとに測って合わせる（`src/body/align.ts`）。写真の服は平らに置かれていないので、柄は少しずつ曲がっている。しまのように同じ柄がくり返すと、よく重なるずらし方がいくつもあるので、上から順に、となりの高さとの差が小さくなるように追いかける
  - えりは服の種類から形を決めて立体で付ける（Tシャツ・ニットのリブ、シャツのえり、立ちえり、フード、ジャケットの下えり。`src/body/collar.ts`）。ベスト・ジレは袖なし
  - 長いパンツは、すそを少し広げて靴の履き口にかぶせる。ブーツのときは、すそを筒の外側に沿わせてかぶせる
- 服の写真の切り抜き（`src/body/cutout.ts`、2026-11-04）
  - 端末の中で動く切り抜きAI U²-Net の小型版（U2-Netp、Apache-2.0、約4.6MB、アプリに同梱）。ONNX Runtime（transformers.js と同じもの）で、WebGPU か wasm で動かす。写真は外に送らない
  - AIの出力を、確かなところから「たぶん服」まで広げてつなぎ（白いボーダーの白い段を取りこぼさない）、小さな穴を埋め、細いかけらを捨てる（`src/body/photoMask.ts`）
  - 動かせない端末では、前の方法（写真のふちの色を背景とみなす）に戻る
- 模様の作り方（`src/body/photoMask.ts` の `planSwatches`、`src/body/render3d.ts` の `garmentTextures`）
  - 前に貼る写真：切り抜きの1画素内側だけを使い、半透明のふちは捨ててからまわりの服の色で埋める（服のまわりに白いふちが出ない）。高さの足りない列（すその丸み）は縦に伸ばさない
  - 生地の見本：服の主な色を k-means で調べ（服全体に散らばる色と、3割以上の色を「地」とする）、地の色以外のかたまり（胸のプリント・ロゴ・ボタン）・背景と同じ色（袖と胴のすき間など）・服のふちを避けた四角から選ぶ。明るさのばらつきとふちの強さが「ふつう」の四角を選ぶので、ボーダーやチェックは模様ごと取れ、無地の服は縫い目や影の少ないところが取れる
  - トップスは胴の範囲（袖を除く）から、えり・肩の縫い目（上の14%）を避けて取る。片方の袖が胴にくっついて写っていても胴の中心がずれないよう、左右の幅をそろえる
  - 袖の色が胴とはっきり違う服（袖の画素の半分以上が胴の地の色のどれとも違う）だけ、袖の見本を別に取る
  - 見本は折り返さずに、つなぎ目なくくり返せる模様にする（柄の傾きを直し、柄のくり返しの長さで切って、両端がいちばん似る道すじでつなぐ。`src/body/tile.ts`）。無地の生地は、見本に入ったしわや折り目の濃淡を弱める（敷き詰めると同じしわがくり返して柄に見えるため）
  - 上に着る服の写真のえり・ハンガーのフック・名札は、肩の線で切って生地の模様でうめる（3Dのえりと二重に見えないように）。えりから胸へ垂れ下がる値札・名札（生地の見本にない色か、見本より大きな同じ色のかたまりで、えりのところにつながるもの。`hangingTags`）も生地の模様でうめる。胸のプリントやロゴはえりにつながらないので残り、下まで続く前立てや前の開きも残る
  - 布の材質は sheen（布らしい光り方）の色を生地の色にする（白いと黒や紺の服が白っぽくかすむ）
- 靴（`src/body/shoe.ts`、`src/body/model3d.ts` の `buildShoes`、2026-11-04）
  - スニーカーと革靴は、本物の靴の3Dの型を使う：Khronos glTF-Sample-Assets の「Materials Variants Shoe」（© 2021 Shopify、CC BY 4.0）
    - `sh tools/body/fetch-shoe.sh` で元データを取ってきて、`node tools/body/build-shoe.mjs` で `src/body/assets/shoe.glb`（約86KB）と模様4枚（下地・塗り分け・凹凸・陰と粗さ、512px）を作る。三角形は約1.4万（6割に減らした）
    - 元データのライセンスはロゴと商標を含まないので、かかとのロゴと、靴底の横の刻印（斜めの線と「FOAM」の文字）を消してある。色の変わる3つの版（Midnight・Beach・Street）の違いから「甲」を見つけ、甲は灰色の濃淡だけにして、アプリで靴の色を掛ける
    - 足の形を体のメッシュから測り、型を足の長さ（かかと約1cm・つま先約2cmのゆとり）・幅・向きに合わせて置く。型は右足用で、左足は左右反転する
    - 型は本物の靴の形なので、体の足のほうを細く・低く・少し短くして靴の中に収める（足首の上でもとの形につなぐ）。履き口より上（ベロ・引き手）は低めにして、パンツのすそから突き出ないようにする
    - スニーカー：布の甲（編み目の凹凸）と白いゴム底。革靴：同じ型で底を薄くし、甲はなめらかでつやのある革、ひもなどは甲の色を濃くした色、底は濃い茶色
    - ライセンスの表記は、アプリの設定画面の「素材のライセンス」にある
  - ブーツは、実物のショートブーツを写真から作った3Dの型を使う：Sketchfab の「Photoscanned Female Ankle Boots」（TunnelVisionStudio、CC BY 4.0。ロゴなし）
    - `sh tools/body/fetch-boot.sh` で元データを取ってきて（Sketchfab から落とすにはログインがいるので、同じデータを置いている GitHub の公開リポジトリから取り、中身が同じかをハッシュで確かめる）、`node tools/body/build-boot.mjs` で `src/body/assets/boot.glb`（約100KB）と模様4枚（512px）を作る。三角形は約1.5万（2割に減らした）
    - 型の向きと大きさは靴の型にそろえる（右足用、かかと z=0・つま先 z=1・床 y=0）。足に合わせて置くのも靴と同じ
    - 模様の画素ごとに型の上の位置と向きを求め、たくさんの向きから見て外から見える面と、筒の中の面（内張り）を分ける。底は高さで分ける。甲・底・内張りの明るさをそろえて灰色の濃淡だけにし、アプリで色を掛ける（革のしわ・すれ・積み革の段は残る）
    - 筒は、脚が中に収まるように広げる（`fitShaft`）。高さごとに脚と型の切り口を取り、脚のまわりの向きごとに、型の外側の面が脚より約7mm外にあるかを調べ、足りないところだけ押し広げる。写真から作った内張りは本物より細いことがあるので、脚の中に入った点は脚の外側まで出す
    - パンツのすそは、ブーツの筒の外側（ひもの結び目や引き手も含めた、いちばん外）より外へ出してかぶせる（`overShoes`）
  - サンダルは、足の形から作る。足の裏の形に沿う厚みのある底と、少し明るい色の中敷き、足の甲に沿う幅広のベルト2本。ベルトは足の切り口を外から包む形（凸包）の上に通して角を丸め、両はしは底の中に入れる（足の指のすき間やくぼみには入らない）。サンダルは足が見えるので、足は小さくせずに中敷きの上にのせる
  - 色は写真の生地の見本の平均色（`Paint.tone`）
- 照明は部屋の環境光（RoomEnvironment）と、やわらかい影

### 開発用のプレビュー
`npx vite --port 5199` で `http://localhost:5199/tools/body/preview.html` を開くと、体型と服を並べて描ける（`tools/body/preview.ts`）。服の写真は `tools/body/.cache/samples/` に置く。

### 分かっている限界
- 切り抜きAIが使えない端末では、ふちの色から決める簡単な方法になるので、背景が散らかった写真や、服と背景が同じ色の写真ではくずれる（その部分は服の色で塗る）
- 背中・袖は生地の見本を敷き詰めるので、大きなプリントや花柄は同じ柄がくり返して見える。花柄のワンピースのスカートは、写真を縦に伸ばすので柄が少し流れる
- 見本を取った四角に縫い目や折り目が入ると、背中・袖にそれがくり返して写る
- 細いひもで胸の下のほうに垂れている値札は、えりにつながって見えないので残る
- 靴の3Dの型はスニーカーとショートブーツの2種類だけ。革靴はスニーカーを革らしくしたもので、パンプスやヒールの形にはならない。ブーツはどれもショートブーツの形になる（ロングブーツはない）。サンダルは足の形から作った2本ベルトの形だけ
- 靴の色は写真の生地の見本の平均色なので、黒いブーツでも、暖かい色の光で撮った写真だと緑がかった灰色に見えることがある
- 写真のえりは使わず、生地の模様で作った立体のえりにするので、えりだけ色が違う服（えりが白いシャツなど）も、えりは胴と同じ色になる
- 写真の採寸から変形したときの体つきは、下着姿の写真で確かめていない（上の BodyM のシルエットは数字で確かめただけ）

## 実在の人の写真で試した結果（2026-10-30）
- Amazon が公開している体型データ BodyM（実在の人の正面・横のシルエットと、巻き尺での実測値。testA の24人）で、読み取った体型と実測値を比べた
  - 胸まわり ±5%、ウエスト ±3%、ヒップ ±3%、脚の長さ ±3%、腕の長さ ±6%、太ももまわり +13%（太め）、肩幅 +22%（データの「肩幅」は骨の幅で、こちらは体の外側の幅なので定義が違う）
  - 身長・体重だけから作る標準体型と比べて、ウエスト（14%→3%）とヒップ（17%→3%）のずれが大きく減る
  - 試して直したこと：腕が肩のすぐ下で胴と重なるのを「腕がついている」と誤判定していた（24人全員）→ わきの下より上は数えない。太ももがくっついていると股を低く測っていた（脚が1割短くなる）→ 腰とひざの点からの見積もりより下にしない。横向きで左右の脚がずれていると厚く出る → 幅の1.15倍まで
- 服を着たファッション写真34枚（ECON のサンプル）：19枚はジャンプや大きなポーズなので撮り直しのお願いに、3枚は体の一部が写っていない、12枚を読み取れた。コートやスカートの写真は服の形が体型になる（コートで胴が太くなる）ので、下着か体にぴったりした服で撮る案内は必須

## まだ確かめていないこと
- 本人の下着や体にぴったりした服での写真（上のデータは切り抜き済みのシルエットなので、背景や服の色で切り抜きがくるう影響は見ていない）
- iPhone Safari での読み取りの速さと、GPU（WebGL）で MediaPipe が動くか（パソコンのブラウザでは1枚1〜2秒。開発環境の描画はソフトウェアなので参考値）
